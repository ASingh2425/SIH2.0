## 4. Verification Limitations & Security Boundaries

1. **Token Un-Vaulting Boundary**:
   - Ephemeral tokens (`PERSON#A72F`) are transmitted to the remote server so the cloud VLM can reference passenger inputs in candidate actions (`action: "TYPE", target: "input-name", value: "PERSON#A72F"`).
   - Real PII values remain stored strictly in `LocalTokenVault` memory on the user's device and are un-vaulted only inside `BrowserExecutor.executeAction()` in client DOM memory immediately prior to DOM event simulation.

2. **Screenshot Base64 Image Inspection**:
   - Screenshot base64 string was decoded and visually inspected. Sensitive visual text regions (such as credit card input fields and canvas text overlays) were confirmed to be obfuscated with solid dark fill boxes (`#020617`).

3. **Egress Validator Integrity**:
   - Service worker egress guard `validateNetworkEgress()` runs independent regex scans on the final stringified JSON payload prior to `fetch()` dispatch. If `zeroRawPIIVerified` evaluates to `false`, transmission is aborted instantly with HTTP 400 rejection.
